# User Data Generator

Этот инструмент генерирует тестовых пользователей, объявления, события пользовательского поведения и загружает их в PostgreSQL.

## Подготовка БД

Из корня репозитория можно поднять PostgreSQL и применить миграции:

```bash
make db-setup
```

Если нужно только поднять сервисы вручную:

```bash
docker compose up -d postgres
make migrate-up
```

## Запуск генератора

Из папки backend:

```bash
go run ./tools/user_data_generator -dsn "postgres://avito-recap:avito-recap@localhost:5433/avito-recap?sslmode=disable" -users 50 -listings 200
```

Или используя make из корня репозитория:

```bash
make seed-data
```

Эта команда автоматически поднимает PostgreSQL, применяет миграции и запускает генератор с параметрами по умолчанию (100 пользователей, 1000 объявлений).

## Параметры

- `-dsn` — строка подключения к PostgreSQL.
- `-users` — количество обычных пользователей, которые будут генерировать поведение.
- `-listings` — общее количество объявлений, создаваемых в системе.
- `-seed` — seed для воспроизводимой генерации данных.

## Сущности генератора

### Пользователи (`model.User`)

Каждый пользователь содержит:

- `ID` — уникальный идентификатор.
- `Username` — логин пользователя.
- `RegisterDate` — дата регистрации в прошлом.
- `Region` — регион пользователя.
- `PriceSegment` — ценовой сегмент: `budget`, `mid`, `premium`.
- `PreferredCategories` — категории, которые пользователь предпочитает.
- `UnlikelyCategories` — категории, которые пользователь посещает реже.
- `SellFrequency` — вероятность, с которой пользователь выступает продавцом.
- `PreferredSellCategories` — категории, в которых пользователь чаще публикует объявления.
- `UnlikelySellCategories` — категории, которые пользователь реже использует при продаже.

### Дефолтные пользователи (`config.DefaultUserConfig`)

Дефолтные пользователи — это специальные пользователи, которые всегда присутствуют в системе и имеют фиксированные настраиваимые характеристики. Они используются для тестирования и демонстрации.

### Категории (`generator.CategoryConfig`)

Категории задаются через конфиг и включают:

- `Name` — название категории.
- `MinPrice` / `MaxPrice` — диапазон цен объявлений.
- `Weight` — относительная частота выбора категории для объявлений.
- `ReturnRate` — как часто пользователи возвращаются к категории при поиске.
- `PurchaseVolume` — вероятность перехода от просмотров к сделкам для категории.

### Объявления (`model.Listing`)

Сгенерированное объявление содержит:

- `ID` — уникальный идентификатор.
- `SellerID` — идентификатор пользователя-продавца.
- `Category` — категория объявления.
- `Price` — цена товара.
- `Region` — регион объявления, совпадающий с регионом продавца.
- `PublishedAt` — время публикации.
- `ClosedAt` — время закрытия объявления, если оно закрыто.
- `DeliveryAvailable` — доступна ли доставка.

### События поведения

Генерируются следующие события:

- `Search` — пользовательский поиск с темой, категорией и фильтрами.
- `View` — просмотр объявления.
- `Share` — отправка объявления кому-либо (происходит после просмотра).
- `Favorite` — добавление объявления в избранное.
- `Contact` — контакт с продавцом (чат, звонок, оффер).
- `CancelDeal` — отмена сделки после контакта (не приводит к созданию сделки).
- `Deal` — успешная сделка между покупателем и продавцом.
- `Review` — отзыв после сделки.
- `Edit` — редактирование объявления продавцом (происходит случайно после публикации).
- `UserEvent` — агрегированное событие активности пользователя.

## Параметры генерации

В `GeneratorConfig` задаются следующие параметры:

- `UserRegistrationYearsAgo` / `SellerRegistrationYearsAgo` — сколько лет назад регистрировались пользователи/продавцы.
- `SellerSelectionRate` — доля пользователей, которые становятся продавцами.
- `ListingHistoryYears` — за сколько последних лет (от текущего момента) распределяются даты публикации объявлений. Объявление обязано быть опубликовано раньше, чем `cutoff` запрошенного recap (`postgres.DatasetRepository.loadListings: WHERE published_at < $2`)
- `RecentActivityWindowMonths` / `RecentActivityBias` — доля интентов (по умолчанию 75%), которая намеренно попадает в последние N месяцев (по умолчанию 14), а не размазывается по всей истории пользователя.
- `SearchCandidatePoolSize` — сколько объявлений возвращает поиск за один интент (раньше было захардкожено 10).
- `PriceBandLowMax` / `PriceBandHighMin` — границы ценовых сегментов.
- `ListingDeliveryProbabilityPercent` — вероятность доступности доставки.
- `ListingPhotosMax` — максимальное количество фото в объявлении.
- `EventDefaultCategory` — категория по умолчанию для событий.
- `EventBaseTimeOffsetHours` — базовое смещение времени событий от регистрации.
- `EventSpreadDays` — разброс событий во времени.
- `IntentCountMultiplier` — множитель для расчета количества интентов на основе PurchaseVolume категорий.
- `IntentCountMin` — минимальное количество интентов на пользователя.
- `IntentCountMax` — максимальное количество интентов на пользователя.
- `IntentSpreadDays` — разброс между разными интентами в днях.
- `EventFavoriteOffsetMinutes` / `EventContactOffsetMinutes` / `EventDealOffsetMinutes` / `EventReviewOffsetHours` — временные смещения между событиями.
- `DealCompletionMinHours` / `DealCompletionMaxHours` — диапазон часов для завершения сделки (сделки завершаются автоматически через случайное время в этом диапазоне).
- `CancelDealProbability` — вероятность отмены сделки после контакта (не приводит к созданию сделки).
- `CancelAfterDealProbability` — вероятность отмены уже созданной сделки (статус "cancelled", без времени завершения).
- `EventRandomSpreadSeconds` — случайное смещение времени событий для реалистичности.
- `ListingEditProbability` — вероятность редактирования объявления.
- `ListingEditMinDays` / `ListingEditMaxDays` — диапазон дней после публикации для редактирования.
- `ShareProbability` — вероятность отправки объявления после просмотра.

## Параметры пользователей и шаблоны поведения

Каждому профилю пользователя соответствует `generator.UserConfig` со следующими параметрами:

- `search` — базовая вероятность выполнения поиска.
- `view` — вероятность просмотра объявления из пула.
- `favorite` — вероятность добавления объявления в избранное.
- `contact` — вероятность контакта с продавцом.
- `deal` — вероятность закрытия сделки.
- `review` — вероятность написания отзыва.
- `SellFrequency` — вероятность того, что пользователь станет продавцом.
- `PriceSegment` — ценовой сегмент покупателя и продавца.
- `PreferredCategories` / `UnlikelyCategories` — категории покупательских предпочтений.
- `PreferredSellCategories` / `UnlikelySellCategories` — категории, в которых пользователь чаще или реже продаёт.
- `Pattern` — шаблон поведения. Влияет на то, как пользователь отбирает объявления и какие действия совершает:
  - `curious` — более склонен добавлять интересные объявления в избранное при высоком score,
  - `intentional` — выбирает больший пул кандидатов для оценки,
  - `high-intent` — оценивает ещё больше объявлений и демонстрирует повышенную активность.

## Алгоритм генерации

1. Генерация пользователей.
   - Первые 3 пользователя используют предопределённые конфигурации для тестирования.
   - Остальные пользователи получают случайные конфигурации через `RandomUserConfig`.
   - Формируются профили покупателя и продавца с разными ценовыми сегментами и категориями.
   - Для продавцов выбираются пользователи с ненулевой вероятностью публикации объявлений.

2. Генерация объявлений.
   - Категория объявления выбирается с учётом `Weight` и предпочтений продавца.
   - Цена определяется в диапазоне `MinPrice` — `MaxPrice` выбранной категории и ценовой сегмент продавца.
   - Время публикации происходит в будущем пределах окна, а `ClosedAt` может определяться позже.
   - Продавец, регион и доставка задаются для каждого объявления.
   - С вероятностью `ListingEditProbability` генерируются события редактирования в диапазоне `ListingEditMinDays`-`ListingEditMaxDays` после публикации.

3. Генерация пользовательских событий (новая воронка).
   - Для каждого пользователя генерируется несколько интентов на основе `PurchaseVolume` предпочитаемых категорий.
   - Каждый интент представляет отдельный поиск в определённой категории.
   - Время каждого интента распределено в периоде активности пользователя.

   **Воронка событий в одном интенте:**

   1. **Search** — поиск возвращает ~10 кандидатов.
   2. **View** — из всех кандидатов фильтруются по вероятности `View`. Только просмотренные объявления переходят дальше.
   3. **Share** — после просмотра, с вероятностью `ShareProbability` происходит отправка объявления.
   4. **Favorite** — только из просмотренных объявлений фильтруются по вероятности `Favorite`.
   5. **Contact** — только из просмотренных объявлений фильтруются по вероятности `Contact` (независимо от избранного).
   6. **CancelDeal** — после контакта, с вероятностью `CancelDealProbability` происходит отмена сделки. Объявления с отменой не переходят к сделке.
   7. **Deal** — только из контактированных (не отменённых) объявлений фильтруются по вероятности `Deal`.
   8. **Review** — только после успешной сделки фильтруются по вероятности `Review`.

   Все события в одном интенте имеют случайное временное смещение в пределах `EventRandomSpreadSeconds` для реалистичности.

## Какие параметры мы симулируем

- Поведение покупателей и продавцов.
- Разные ценовые сегменты (`budget`, `mid`, `premium`).
- Предпочтения категорий и редкие категории.
- Вероятность возвращения к категории (`ReturnRate`).
- Преобразование просмотров в покупки (`PurchaseVolume`) — влияет на количество интентов.
- Наличие доставки.
- Временную динамику публикации и закрытия объявлений.
- Взаимодействие между разными пользователями через настоящие объявления: пользователь не взаимодействует со своими собственными листингами.
- Воронку преобразования: Search → View → Share → Favorite → Contact → CancelDeal/Deal → Review.
- Контакт происходит независимо от избранного (можно контакт без favorite).
- Отмену сделок после контакта (не приводит к созданию сделки для того же пользователя).
- Редактирование объявлений продавцами в случайное время после публикации (только для открытых объявлений).
- Отправку объявлений после просмотра.
- Количество интентов зависит от интересов пользователя и категории.
- Корректный временной порядок всех событий (проверяется тестами).
- Единоразовость сделки на объявление (одно объявление → одна сделка максимум).
- Отмена сделки происходит до закрытия объявления.
- Редактирование происходит только для открытых объявлений.
