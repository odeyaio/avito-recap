# Каталоги правил

`achievements.yaml` и `behaviors.yaml` — версионируемые источники определений ачивок и поведенческих типов. Они не загружаются автоматически при старте приложения или базы: импорт выполняется одной транзакцией отдельной командой после миграций.

```bash
make migrate-up
DATABASE_URL="postgres://..." make catalog-import
```

Файлы связаны с `achievement-catalog.schema.json` и `behavior-catalog.schema.json` директивами `yaml-language-server`. IDE с поддержкой YAML Schema показывает обязательные поля, допустимые операторы и ошибки типов при редактировании.

## Правила

Правило — рекурсивное дерево из логических групп и условий:

- `all` — истинны все вложенные правила;
- `any` — истинно хотя бы одно вложенное правило;
- `metric` — ключ заранее рассчитанной метрики, например `activity.active_months`;
- `value` — порог или ожидаемое значение.

Операторы:

| Оператор | Значение         | Аналог |
| -------- | ---------------- | ------ |
| `eq`     | равно            | `==`   |
| `neq`    | не равно         | `!=`   |
| `gt`     | больше           | `>`    |
| `gte`    | больше или равно | `>=`   |
| `lt`     | меньше           | `<`    |
| `lte`    | меньше или равно | `<=`   |

`gt`, `gte`, `lt` и `lte` применяются только к числам. `eq` и `neq` поддерживают числа, строки и boolean. Если рассчитанной метрики нет, условие считается ложным: ошибка в имени метрики не должна случайно выдать пользователю ачивку.

Пример:

```yaml
rule:
  all:
    - metric: activity.active_months
      operator: gte
      value: 10
    - metric: activity.returned_after_long_break
      operator: eq
      value: true
```

`iconKey` — относительный ключ файла в S3. Публичный URL строится сервисом из CDN/base URL и этого ключа.

## Следующие действия

Каждый тип в `behaviors.yaml` содержит `defaultAction`:

- `code` — стабильный код намерения;
- `title` — безопасная формулировка по умолчанию и инструкция для ИИ;
- `resolver` — имя Go-стратегии, которая проверяет актуальные данные, выбирает цель и строит `href`.

Каталог хранит только стратегию. Результат её выполнения для пользователя сохраняется один раз в `recap_next_action`; персональные `title` и `text` сохраняются в `recap_presentations`.

Пороги в каталогах — начальная конфигурация MVP. При изменении порогов или смысла правил нужно повысить корневой `version`. Импорт сохраняет версии в `rule_version` соответствующих таблиц и обновляет записи по стабильному `code`.
